How a failure qualifies for rerun
---------------------------------
--only-rerun / --rerun-except are regex lists. The match text is the current attempt's exception, formatted as "TypeName: " plus str(exception), walked along __cause__ (and __context__ for --only-rerun). It is not the traceback.

A failed report is a terminal (not rerun) error when that match says so. _should_not_rerun then refuses a rerun on attempt count, a non-failure, xfail, a terminal error, or a false flaky condition. The condition receives the exception object for this attempt; the plugin does not read frame locations from it.

pytest-rerunfailures 16.7 qualifies a failure for rerun by regex-searching the current attempt's "TypeName: message" string (or an exception-class isinstance check) and never compares traceback file or line locations between attempts, so it has no same_failure_modulo_line check that would accept a one-line shift of the same assertion only after masking `.py:<n>`.
