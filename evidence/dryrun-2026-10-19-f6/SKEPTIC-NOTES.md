# Skeptic notes after the F6 runs

Read against `inputs/dryrun-2026-10-19-f6/SKEPTIC-F6.md`. These are things in this session that can move a result without being the named order dependence.

## What the runs actually showed

C1, C2, and C3 at `76eeb3f` fail 3/3 with the M4 `TypeError` (`test_flight_request_client` for C1 and C2, `tunes_request_client` for C3), polluter group before victim. The same three pass 3/3 at `148c1c9` with the polluter still first. R1, R2, and R3 pass 3/3 at both commits with the victim group first. That is the certificate rule in `SPEC-fastlane-F6.md`.

C4 is not that pattern. At `76eeb3f`, `rspec/C4-76eeb3f-r1.log` line 42 prints `#get_build_deliveries` with no `FAILED` mark. The 16 failures are `provisioning_client_spec.rb` examples, class `WebMock::NetConnectNotAllowedError`, first `Failure/Error` at `Spaceship::ConnectAPI.login(...)`. `TypeError` count in those three logs is 0. R4 passes 3/3 at both commits, and C4 at `148c1c9` passes 3/3. The spec's guard (M4 message required, swapped order must pass) is what keeps C4 at `CERTIFIED n`. Calling C4 the named polluter of `build_delivery:5` would be the artefact.

The fix commit's `spaceship/spec/spec_helper.rb` stubs `SIRP::Client#start_authentication` before every `./spaceship/` example and says, in that file, that without the stub a login computes a real SRP value, matches no WebMock body, and fails with `WebMock::NetConnectNotAllowedError` depending on what ran first. At the prefix that stub lives on the shared login example, so it is installed when `build_delivery` runs first (R4 passes) and not when `provisioning_client_spec` runs first (C4's 16 WebMock failures). That is order, and it is also a missing stub, which is the case `SKEPTIC-F6.md` item 1 names.

## Environment, not the spec order

- The box had no Docker engine. `sudo -n apt-get install -y docker.io` installed `docker.io 26.1.5+dfsg1`. `policy-rc.d` refused the service start, so `containerd` and `dockerd` were started by hand. `q6.log` server version is `26.1.5+dfsg1`, the same version string as F4, not the same daemon process.
- The image was rebuilt. `q6.log` image id is `sha256:1f3248c0b71fb38ce02d05bc3cee8da5257792360158a660b83518c8cb827e63`. F4's id in `evidence/dryrun-2026-10-19-f4/q4.log` line 7 is `sha256:1a9f5251d78b846341bad2d4b1992d89f71e97d3d7416146b45d2dbecbd75481`. Docker reported `transferring dockerfile: 315B` for this build, the same figure as `evidence/dryrun-2026-10-19/q2-ruby-image.log`. Inside the image, `ruby -v` is `ruby 3.1.7p261 (2025-03-26 revision 0a3704f218) [x86_64-linux]`, `bundle -v` is `Bundler version 2.6.9`, `gem list bundler` is `bundler (2.6.9, default: 2.3.27)`, and `bundle exec rspec --version` is RSpec 3.12 with rspec-core 3.12.2. Those strings match F4. The image digest does not, so apt indexes or layer metadata can differ. No local Ruby fallback was used.
- `bundle _2.6.9_ install` ran fresh against rubygems.org into `vendor/bundle` (`BUNDLE_APP_CONFIG=/src/.bundle`, path already `vendor/bundle` in the tarball's `.bundle/config`). Both logs end `Bundle complete! 29 Gemfile dependencies, 174 gems now installed` and `bundle_install_exit:0`. F4 reused an earlier `vendor/bundle`. Native extensions were compiled in this image. The lockfile is what the install used.
- Codeload tarballs were re-fetched by `reverse/recon.sh` from an empty directory. `recon-replay.log` is byte-identical to `reverse/recon.log` (`cmp` exit 0 in `q6.log`). Tarball sha256 values match the SPEC lines `078c5e59…` and `db53c7bc…`. The trees have no `.git`. `git rev-parse HEAD` printed `fatal: not a git repository` and `git_rev_parse_failed` in both version logs. Commit identity is the tarball directory name plus that sha256, not a git object in the tree.
- Every run prints `[Coveralls] Set up the SimpleCov formatter`. `FASTLANE_SKIP_UPDATE_CHECK` was unset, same as F4, so `Coveralls.wear!` runs. A coveralls POST is network. `rspec_exit_matches_docker_exit True` in `q6.log`: the exit code is the RSpec status. `coverage/.resultset.json` on each mounted tree is shared across that commit's 30 runs and was absent at extract time. Pass/fail did not.
- `docker run --rm` drops container `/tmp` (`fastlane_tests`, RSpec persistence file) between reps. It does not drop the mounted `coverage/` directory.
- C4 at `76eeb3f` is the one nondeterministic body: the unstubbed SRP public value changes the WebMock `a` field, so the first message line is not byte-identical across r1/r2/r3. The class, the summary `17 examples, 16 failures`, the documentation order, and the 16 failed example ids are identical (`diff` of the `^rspec ` lines). `rep_disagreements 0` uses that definition. The random `a` is the unstubbed client, not RSpec's `--seed`.
- No pytest and no pytest-randomly. The sealed holdout file was not opened. Scope is these files, these two commits, this image.
